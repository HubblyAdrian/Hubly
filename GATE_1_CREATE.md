# Gate 1 — CREATE

## Goal

A real person successfully uses Create — without us standing next to them.

Gate 1 does **not** close because every visual detail is perfect.  
Gate 1 closes because **validated customers** would use it.

## Technical bar (must be true)

- [ ] AI conversation works with OpenAI
- [ ] Website generates correctly
- [ ] Booking generates correctly
- [ ] Home is ready

These are prerequisites — not the finish line.

## Product bar (how Gate 1 actually closes)

### Watch 5 people go through `/demo`

1. Pick five real operators (cleaners, photographers, trainers, detailers, etc.).
2. Give them the URL. **Don’t help. Don’t explain.**
3. Observe only.
4. After they finish, ask **only** these questions:

| # | Question |
|---|----------|
| 1 | What do you think Hubly does? |
| 2 | Would you publish this website? |
| 3 | Would you let customers book through it? |
| 4 | What confused you the most? |
| 5 | Would you pay to use this? |

5. Fix the **biggest patterns** from their answers — not our opinions.

### Close rule

If **3 of 5** independently say they would actually use this for their business (publish / book / pay signals line up), Gate 1 may close and we move to Gate 2.

Perfect is a moving target. **Validated is measurable.**

## What is NOT an MVP blocker

- Logo is initials — fine for Gate 1.
- Pixel-perfect motion, brand polish, or “feels magical in a vacuum.”

## What IS the goal instead

- **Website feels professional enough to publish.**
- Booking feels usable enough to send to a customer.
- The person understands what Hubly built without a tour.

## Cursor build checklist (experience exists)

### Landing
- [ ] Landing page
- [ ] Clear promise
- [ ] AI starts immediately
- [ ] No unnecessary clicks

### Conversation
- [ ] Real OpenAI conversation
- [ ] Feels like ChatGPT
- [ ] AI remembers everything
- [ ] AI makes assumptions
- [ ] AI asks only when needed

### Live Build
- [ ] Website builds live
- [ ] Logo builds live (initials OK)
- [ ] Packages appear
- [ ] Booking appears
- [ ] Brand updates live

### Reveal
- [ ] Reveal shows what was built
- [ ] Website preview (real surface)
- [ ] Booking preview (real surface)
- [ ] CRM preview (honest — empty OK)
- [ ] Packages preview

### Enter Hubly
- [ ] Everything already exists
- [ ] Smooth transition
- [ ] Home proves readiness (open website / booking / CRM)

## DONE WHEN

Technical bar is met **and** validation passes (3/5 would use it).

A customer should be able to say:

> "Hubly built my business."

…without us explaining what just happened.

## How we judge

Open `/demo`.

Nothing is checked because code merged.  
Items check only when the customer experience is true **or** validation notes prove it.

## Work rule (rest of Gate 1)

**Stop polishing in isolation. Start polishing from user behavior.**

- Do not add features.
- Do not chase internal taste passes.
- Highest-value work: run sessions, write what broke, fix the top patterns.
- Show, don’t tell. Never fake completeness.

After each revision that follows a session, answer:

1. What customer experience improved? *(cite session evidence)*
2. What still doesn’t meet our quality bar?
3. What are the remaining blockers before Gate 1 can close?
4. If you had to launch Gate 1 tomorrow, what are the three reasons you’d still hesitate?

## Acceptance demo (internal smoke)

```
Open /demo
Type: I'm an independent fitness trainer.
Go through the experience naturally.
```

Internal smoke is required. **It does not close the gate.**  
Closing requires the 5-person validation above.
